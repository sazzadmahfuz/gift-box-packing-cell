# Engineering Notebooks

Each student keeps **one Markdown file per week**, with dated entries on every project working day. Write during or after the work and push the update that day. Record real progress, including unsuccessful tests and blockers. Do not invent activity to fill an inactive day.

## What to Record

- Weekly goals, task IDs, expected outputs, and estimated hours.
- Daily date, task, actual time, partner, and your own contribution.
- Decisions and evidence: code, CAD, measurements, screenshots, or tests.
- Failures, blockers, help needed, and next action.
- Weekly reflection: planned versus completed work, actual hours, learning from cooperation, reviewer feedback, and unfinished work.

See the [blank weekly template](weekly-template.md) and [fictional example](example-entry.md). Commit counts do not measure contribution.

## Later Weeks

Create `week-02/` through `week-08/` as needed. Copy the weekly template once per student into the new folder, fill the actual dates, and add links here. Keep the same student filenames. The online review time comes from Moodle; the weekly reflection need not be on Friday.

From a file in a weekly folder, use `../../testing/` for test records and `../../software/` for code. These paths are examples: link to actual files you create and check the links on GitHub. Use evidence filenames that identify the date and test.

If upload access fails, save the entry locally, tell the team, and resolve it promptly. Do not replace the week's real records with a reconstructed success story.
